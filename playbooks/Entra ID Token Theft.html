High Severity Alert

Entra ID Token Theft

SOC Analyst Response Guide for session cookie theft and offline access detection in Microsoft Entra ID environments.

T1539 - Steal Web Session Cookie T1528 - Steal Application Access Token Credential Access
01

Immediate Triage

Within the first 15 minutes, validate the alert and gather critical context to determine if containment is needed.

0-5 MINUTES

Validate the Alert

  • Check if user's location/IP matches normal behavior patterns
  • Review "Detected Offline" context — indicates token used without active session
  • Correlate timestamps between legitimate login and suspicious activity
  • Check for impossible travel scenarios
5-15 MINUTES

Gather Context

  • Pull Entra ID Sign-in Logs for affected user (last 24-72 hours)
  • Look for anomalies: unfamiliar IPs, new devices, unusual user agents
  • Review Audit Logs for privilege escalation or config changes
  • Check Conditional Access policy evaluation results
⚠️
Key Indicator

"Detected Offline" typically means a refresh token or session cookie was used to obtain new access tokens without the user being actively authenticated — a strong indicator of token theft.

02

Containment Actions

If malicious activity is confirmed, execute these containment steps immediately to limit attacker access.

Token & Session Revocation

  • Revoke all refresh tokens
    Revoke-AzureADUserAllRefreshToken -ObjectId <user-id>
  • Force re-authentication
    Disable then re-enable the user account in Entra portal
  • Reset user password
    Require password change on next sign-in

Persistence Removal

  • Review OAuth app consents
    Check for suspicious enterprise app permissions granted by user
  • Check mail rules & forwarding
    Look for inbox rules, forwarding addresses, or delegates in M365
  • Audit MFA methods
    Verify no unauthorized authentication methods were added
🚨
Critical: Check for OAuth Abuse

Attackers commonly use illicit OAuth consent grants as a persistence mechanism. Review enterprise applications with delegated permissions, especially Mail.Read, Files.ReadWrite, and User.Read.All.

03

Investigation Checklist

Investigation Area What to Check Priority
Authentication MFA status, Conditional Access policy hits/bypasses, authentication methods used Critical
Device Compliance Is the device compliant/managed? Any new device registrations? Critical
Applications Suspicious OAuth consents, enterprise app access, service principal activity Critical
Lateral Movement SharePoint, Teams, OneDrive, Azure resource access from suspicious sessions High
Persistence New MFA methods, service principals, registered devices, app registrations High
Data Access File downloads, email access, sensitive resource enumeration Medium
04

Detection & Hunting Queries

Use these KQL queries in Microsoft Sentinel or Log Analytics to investigate the incident.

User Sign-in Analysis 
// Analyze sign-ins for the affected user
SigninLogs
| where UserPrincipalName == "affected_user@domain.com"
| where TimeGenerated > ago(7d)
| project TimeGenerated, Location, IPAddress, 
          AppDisplayName, DeviceDetail, Status, 
          ConditionalAccessStatus, RiskState
| order by TimeGenerated desc
Token Replay Detection 
// Detect potential token replay attacks
SigninLogs
| where TimeGenerated > ago(24h)
| where TokenIssuerType == "AzureAD"
| where AuthenticationRequirement == "singleFactorAuthentication"
| where ResultType == 0
| summarize count(), dcount(IPAddress), 
            make_set(IPAddress) by UserPrincipalName
| where dcount_IPAddress > 3
Suspicious OAuth Consent Grants 
// Find potentially malicious OAuth app consents
AuditLogs
| where TimeGenerated > ago(30d)
| where OperationName == "Consent to application"
| extend InitiatedBy = tostring(InitiatedBy.user.userPrincipalName)
| extend AppName = tostring(TargetResources[0].displayName)
| project TimeGenerated, InitiatedBy, AppName, 
          TargetResources, AdditionalDetails
Impossible Travel Detection 
// Identify impossible travel scenarios
SigninLogs
| where TimeGenerated > ago(7d)
| where ResultType == 0
| summarize Locations = make_list(Location), 
            Times = make_list(TimeGenerated),
            IPs = make_list(IPAddress) by UserPrincipalName
| where array_length(Locations) > 1
| mv-expand Locations, Times, IPs
05

Escalation Criteria

Escalate to IR Team

  • Evidence of data exfiltration (bulk downloads, API data access)
  • Privilege escalation (Global Admin, Exchange Admin, etc.)
  • Attacker persistence mechanisms confirmed
  • Multiple affected users identified
  • Access to sensitive workloads (Azure resources, M365 admin)

Escalate to Management

  • Executive or VIP account compromised
  • Regulatory data potentially accessed
  • Third-party/customer data exposure risk
  • Business email compromise indicators
  • Ransomware or destructive activity signs
06

Prevention & Hardening

Recommended Controls

Control Description
Token Protection (Preview) Bind tokens to device, preventing use on other machines
Continuous Access Evaluation Near real-time token revocation for critical events
Compliant Device Requirement Require Intune-managed, compliant devices via Conditional Access
Sign-in Risk Policies Block or require MFA for high-risk sign-ins
Admin Consent Workflow Prevent users from consenting to apps without approval
